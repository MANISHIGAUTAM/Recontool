# Output-File Contract — every tool, every capability

> Rule: **every integrated tool MUST produce at least one output file, named by what it
> produced.** A tool that does several jobs (e.g. a fuzzer that brute-forces *paths* and
> *vhosts*) writes each job to its own typed file. Path findings go to path files,
> subdomain findings go to subdomain files — never mixed.

This is the bridge between "a tool ran" and "the database learned something". The AI
key-extractor (see [`01-event-based-state-matrix.md`](01-event-based-state-matrix.md))
reads these typed files, not raw stdout.

---

## 1. Directory layout (per scan)

```
artifacts/<scan_id>/
├── raw/<tool>/<input>.{json,txt}        # verbatim tool output (provenance, unchanged)
├── by-type/                             # NORMALIZED, typed, append-only, deduped
│   ├── subdomains.txt                   # one value per line, lower-cased, *.-stripped
│   ├── subdomain_candidates.txt         # UNCONFIRMED permutations (dnsgen/gotator/alterx)
│   ├── live_hosts.txt                   # scheme://host:port that responded
│   ├── ips.txt
│   ├── cidrs.txt   asns.txt   certs.jsonl
│   ├── urls.txt    paths.txt  endpoints.txt
│   ├── params.txt  emails.txt buckets.txt
│   ├── tech.jsonl  services.jsonl  tags.jsonl
│   ├── findings.jsonl
│   └── secrets_redacted.jsonl           # hash+mask+location only, never raw secrets
├── by-type/per-tool/<tool>/<type>.txt   # same data, partitioned by tool (provenance view)
├── js/<host>/*.js                       # harvested JS bodies
└── screenshots/*.png
```

- **`raw/`** = provenance (what the tool literally said). Never parsed by the key-extractor.
- **`by-type/`** = the canonical, append-only, deduped corpus the loop consumes.
- **`by-type/per-tool/`** = the same records partitioned per tool, so you can answer "what
  did *subfinder* alone find?" — this is the per-tool history the request asked for.

Append-only + dedupe (via `anew`-style set semantics) is what gives you **"detect new live
things while keeping everything previously detected by each tool"**: the file is the union
over all runs; a diff against the previous snapshot yields the *new* rows for this run.

## 2. Naming rule

`by-type/<produced_type>.txt`  — driven by the tool's `produces`, not its name.

For a tool with one output type, the file is simply that type (`subfinder → subdomains.txt`).
For a **multi-capability** tool, each mode maps to its own type/file:

| Tool | Mode | Produces | File |
|------|------|----------|------|
| `ffuf` | dir | path | `paths.txt` |
| `ffuf` | vhost | subdomain | `subdomains.txt` |
| `ffuf` | param | param | `params.txt` |
| `gobuster` | dir / dns / vhost / s3 | path / subdomain / subdomain / bucket | `paths` / `subdomains` / `subdomains` / `buckets` |
| `katana` | crawl / jc | url / js_file | `urls.txt` / `js_files.txt` |
| `gau` | urls / js | url / js_file | `urls.txt` / `js_files.txt` |
| `dnsx` | resolve / cname | ip / subdomain | `ips.txt` / `subdomains.txt` |
| `tlsx` | tls / san | cert / subdomain | `certs.jsonl` / `subdomains.txt` |
| `httpx` | probe / tech | live_host / tech | `live_hosts.txt` / `tech.jsonl` |
| `amass` | enum / intel | subdomain / domain+asn | `subdomains.txt` / `domains.txt` |
| `nmap` | -sV / NSE | service / finding | `services.jsonl` / `findings.jsonl` |

The full per-tool mapping is sheet **`05_Output_File_Map`** in
[`data/recontool_state_matrix.xlsx`](../../data/recontool_state_matrix.xlsx) and is
regenerated by `python -m recontool.inventory.build_state_matrix`.

## 3. Implementation hook

Today `adapters/generic.py` saves raw output only (`ctx.artifacts.save_raw/save_text`).
The change is small and central: after `emit_events(...)` produces normalized `Event`s,
route each event to its typed file by `event.type` (and, for multi-mode CLI tools, by the
mode that produced it). One helper in `core/artifacts.py`:

```python
def append_typed(scan_id, tool, produced_type, values):
    # writes/dedupes by-type/<file>.txt AND by-type/per-tool/<tool>/<file>.txt
    fname = PRODUCES_FILE[produced_type]            # same map as the workbook
    artifacts.append_unique(f"by-type/{fname}", values)
    artifacts.append_unique(f"by-type/per-tool/{tool}/{fname}", values)
```

Because the generic engine already classifies every emitted record by entity type, the
split is automatic for all 500+ declarative tools — no per-tool code.
